# Address

A Java application built with Maven as part of the Dufuna Java Programme (Berlin cohort). The project establishes the base structure for the `address` application and currently contains an introductory console program.

## Overview

This repository holds the `address` Maven project. At this stage it includes:

- A standard Maven project layout
- A single entry point class, `AddressApp`, which prints a greeting to the console
- Build configuration targeting Java 17

The project will grow as the programme progresses.

## Tech Stack

| Tool | Version |
| --- | --- |
| Java (Amazon Corretto) | 17 |
| Apache Maven | 3.9.x |
| Git | Any recent version |
| IDE (recommended) | IntelliJ IDEA |

## Prerequisites

Make sure the following are installed and available on your `PATH`:

- **JDK 17** (Amazon Corretto 17 recommended)
- **Apache Maven 3.9 or later**
- **Git**

Verify your setup:

```bash
java -version
mvn -version
git --version
```

`java -version` should report version 17, and the `Java version` line in the `mvn -version` output should also show 17. If Maven reports a different Java version, check that `JAVA_HOME` points to your JDK 17 installation.

## Getting Started

Clone the repository:

```bash
git clone https://github.com/Stormmzyy/dufuna-berlin-jesutomiwoogundare.git
cd dufuna-berlin-jesutomiwoogundare
```

Build the project:

```bash
mvn clean install
```

A successful build ends with `BUILD SUCCESS` and produces `target/address-1.0-SNAPSHOT.jar`.

## Usage

### From the command line

After building, run the application from the project root:

```bash
java -cp target/classes com.dufuna.berlin.jesutomiwoogundare.address.AddressApp
```

Expected output:

```
Hello, World!
```

### From IntelliJ IDEA

1. Open the project folder in IntelliJ IDEA (**File > Open**). It will be detected as a Maven project.
2. Set the project SDK to Java 17 under **File > Project Structure > Project**.
3. Open `AddressApp.java` and click the run icon next to the `main` method.

## Configuration

Project settings are defined in `pom.xml`:

| Property | Value |
| --- | --- |
| `groupId` | `com.dufuna.berlin.jesutomiwoogundare` |
| `artifactId` | `address` |
| `version` | `1.0-SNAPSHOT` |
| `maven.compiler.source` / `maven.compiler.target` | `17` |
| `project.build.sourceEncoding` | `UTF-8` |

No environment variables or external services are required to run the application.

## Development Workflow

1. Make your changes in `src/main/java`, keeping each class in the package that matches its directory.
2. Rebuild and confirm the build passes:

   ```bash
   mvn clean install
   ```

3. Run the application to verify the output.
4. Commit and push your changes:

   ```bash
   git add .
   git commit -m "Short description of the change"
   git push
   ```

Build output (`target/`) and IDE-specific files (`.idea/`, `*.iml`) are excluded through `.gitignore`.

## Conventions

- Class names must match their file names (for example, `AddressApp` lives in `AddressApp.java`).
- Package names must mirror the directory structure under `src/main/java`.
- `pom.xml` stays at the root of the project.
